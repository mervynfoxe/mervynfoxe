## Contributing

If you'd like to submit a patch for one of my projects, first off thanks in advance for your contribution!

### Cloning repositories

I host "canonical" versions of all my project repos on [my own server](https://git.mervyn.online/fox?tab=repositories), which is publicly accessible but not open to user registration. I try to mirror most of my active work on other public hosts such as [GitHub](https://github.com/mervynfoxe) or [Codeberg](https://codeberg.org/mervynfoxe), so feel free to use those as sources for cloning/forking.

### Submitting patches via email

Email is my preferred method of accepting patches for anything less "public." I know it's a dated and complicated method, but it's easier than trying to monitor PRs across every platform I mirror my repos to, and I keep my main server closed to registration. If you don't see conflicting details in a given project's info, then this route is a safe bet, but do check the README just in case a specific project prefers PRs.

- Make your changes in your local repository
- Create your patch with the project name in the prefix (e.g. `git format-patch <ref> --subject-prefix="PATCH <project-name>"` or `git config format.subjectPrefix "PATCH <project-name>"`)
- If your patch contains multiple commits or involves detailed changes, provide a cover letter
- Send your patch(set) to me directly at `patches@dev.mervyn.online`

If you need help sending patches over email, check out [git-send-email.io](https://git-send-email.io/).

### Opening pull requests

As a fallback, I do occasionally check my mirrored repos for PRs, if you're more comfortable submitting changes that way, but I may be slower to address those. Because they're mirrors, I generally won't merge the PR in directly but will download your patch from it and apply it manually, then respond on the PR.

**For sensitive or high security issues, please always contact or email a patch to me directly.** If you're not comfortable sending email patches, just reach out and we'll work something out.
